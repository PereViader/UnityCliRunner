# Regression Report: Release v0.6.0 CI Integration Test Failures

**Date:** 2026-08-26  
**Failed Workflow Run:** [GitHub Actions Run 32906675130 (Job 97992243160)](https://github.com/PereViader/UnityCliRunner/actions/runs/32906675130/job/97992243160)  
**Affects:** Release / Integration Test Suite (`test.sh`)  
**Status:** Resolved  

---

## 1. Summary

During the GitHub Actions release workflow for version 0.6.0, the test runner failed with **18 failures out of 34 integration tests**:
```
INTEGRATION TESTS FAILED: 18 failure(s) out of 34 test(s) run
##[error]Process completed with exit code 1.
```

Investigation identified two primary root causes and one repository file structure issue introduced in commit `d834913` / `4b929a0`:
1. **Bash `/dev/tcp` stderr output on connection refusal** during socket polling (causing 14 test failures due to stdout/stderr mismatch against verified snapshots).
2. **Duplicate metadata reference injection in dynamic Roslyn compilation** causing `error CS0433: The type 'X' exists in both 'UnityEngine.CoreModule...' and 'UnityEngine...'` (causing 4 eval test failures).
3. **Accidental overwriting of root CLI script** with the full package CLI script instead of the thin bootstrap forwarding wrapper.

---

## 2. Detailed Symptoms & Diagnostics

### Issue A: Bash `/dev/tcp` Stderr Leakage (14 Tests Failed)

#### Symptoms
Tests failed output snapshot comparisons due to unexpected lines injected into the test output:
```diff
--- IntegrationTests/TestFilterCategory/output.online.verified.txt
+++ IntegrationTests/Temp/norm_out_online.txt
@@ -1,7 +1,9 @@
 Detected running Unity instance (via UnityLockfile).
+./cli: line 224: /dev/tcp/127.0.0.1/33031: Connection refused
+.
 Unity is ready!
 Sending command to run editmode tests...
 Waiting for tests to complete...
```

#### Affected Tests
`TestCompileWarningsAndPass`, `TestNoWarningsAndFailures`, `TestNoWarningsAndSkipped`, `TestStopTests`, `TestExecuteSuccess`, `TestExecuteFailure`, `TestExecuteNotFound`, `TestExecuteReturnsInt`, `TestExecuteReturnsObject`, `TestExecuteParams`, `TestFilterCategory`, `TestRefresh`, `TestPollRefreshNonBlocking`, `TestRecompile`.

#### Root Cause
In the legacy CLI script, `send_socket_cmd` had been changed to:
```bash
elif exec 3<>/dev/tcp/127.0.0.1/$port 2>/dev/null; then
```
In Bash, redirections on commands are evaluated strictly from **left to right**. When `exec 3<>/dev/tcp/...` attempted to connect while Unity's socket server was temporarily not listening (e.g., during domain reloads or compilation cycles):
1. `3<>/dev/tcp/...` failed immediately with `Connection refused`.
2. Because `2>/dev/null` was specified *after* `3<>`, standard error had not yet been redirected.
3. Bash printed the connection error to the process's standard error stream, which was captured by `test.sh` into `raw_out`.

---

### Issue B: Ambiguous Type References in Dynamic Roslyn Eval (4 Tests Failed)

#### Symptoms
Eval integration tests using types from `UnityEngine` failed with compile-time ambiguity errors:
```
eval(1,9): error CS0433: The type 'Mathf' exists in both 'UnityEngine.CoreModule, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null' and 'UnityEngine, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null'
eval(1,1): error CS0433: The type 'Debug' exists in both 'UnityEngine.CoreModule, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null' and 'UnityEngine, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null'
eval(1,1): error CS0433: The type 'GameObject' exists in both 'UnityEngine.CoreModule, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null' and 'UnityEngine, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null'
```

#### Affected Tests
`TestEvalExpression`, `TestEvalVoidStatement`, `TestEvalDestroyedObject`, `TestEvalGameObject`.

#### Root Cause
In `Packages/com.pereviader.unityclirunner/Editor/RoslynCompilerHelper.cs`, `BuildMetadataReferences` attempted to assemble compilation metadata references by:
1. Iterating `AppDomain.CurrentDomain.GetAssemblies()`
2. Recursively scanning and adding every `.dll` in `Editor/Data/UnityReferenceAssemblies/`
3. Recursively scanning and adding every `.dll` in `Editor/Data/Managed/`

In modern Unity (including Unity 6 in the Linux CI container `unityci/editor:ubuntu-6000.0.77f1-base-3`), core types (`Mathf`, `Debug`, `GameObject`, etc.) are defined in `UnityEngine.CoreModule.dll`. However, the disk folders `UnityReferenceAssemblies/` and `Managed/` also contain legacy facade / multi-targeting `UnityEngine.dll` assemblies.

Because `addedLocations` only deduplicated by file path, Roslyn was provided both `UnityEngine.CoreModule.dll` and `UnityEngine.dll` as metadata references. When resolving types under the `UnityEngine` namespace, Roslyn found conflicting definitions in both assemblies and failed with `CS0433`.

---

### Issue C: Root CLI Runner Script Overwrite

#### Root Cause
During the implementation of the `eval` feature in commit `d834913`, the root CLI runner script was directly overwritten with the full implementation script (~1370 lines) rather than maintaining the thin bootstrap forwarding wrapper (~120 lines).

---

## 3. Solutions & Fixes Applied

### 1. Silent Socket Probing in Subshell
Replaced the inline `exec 3<>` condition with a subshell probe where `stdout` and `stderr` are redirected prior to evaluation:
```bash
elif (echo >/dev/tcp/127.0.0.1/$port) >/dev/null 2>&1; then
  response=$(
    if exec 3<>/dev/tcp/127.0.0.1/$port 2>/dev/null; then
      echo "$cmd" >&3 2>/dev/null
      if read -t "$timeout" line <&3 2>/dev/null; then
        echo "$line"
      fi
      exec 3>&- 2>/dev/null
    fi
  ) 2>/dev/null
```
- Completely suppresses any connection refusal messages to stderr.
- Ensures file descriptor 3 is cleanly managed inside the subshell without leaking into the caller environment.

### 2. AppDomain Loaded Assemblies & Name Deduplication in Roslyn Helper
Replaced disk directory scanning with AppDomain reflection and simple-name deduplication:
```csharp
private static void BuildMetadataReferences()
{
    var refList = new List<object>();
    var addedLocations = new HashSet<string>(StringComparer.OrdinalIgnoreCase);
    var addedAssemblyNames = new HashSet<string>(StringComparer.OrdinalIgnoreCase);

    void AddRef(string path, string assemblyName = null)
    {
        if (string.IsNullOrEmpty(path) || !File.Exists(path)) return;
        if (!addedLocations.Add(path)) return;

        if (!string.IsNullOrEmpty(assemblyName))
        {
            if (!addedAssemblyNames.Add(assemblyName)) return;
        }

        // Add MetadataReference via reflection
        ...
    }

    void AddAssembly(Assembly asm)
    {
        if (asm == null || asm.IsDynamic) return;
        try
        {
            string loc = asm.Location;
            if (string.IsNullOrEmpty(loc) || !File.Exists(loc)) return;
            string name = asm.GetName().Name;
            AddRef(loc, name);
        }
        catch { }
    }

    foreach (var asm in AppDomain.CurrentDomain.GetAssemblies())
    {
        AddAssembly(asm);
    }

    // Explicit core fallbacks
    try { AddAssembly(typeof(object).Assembly); } catch { }
    try { AddAssembly(typeof(System.Linq.Enumerable).Assembly); } catch { }
    try { AddAssembly(typeof(System.Collections.Generic.List<>).Assembly); } catch { }
    try { AddAssembly(typeof(UnityEngine.Object).Assembly); } catch { }
    try { AddAssembly(typeof(UnityEngine.GameObject).Assembly); } catch { }
    try { AddAssembly(typeof(UnityEditor.Editor).Assembly); } catch { }

    s_CachedMetadataReferences = refList;
}
```

### 3. Restored Thin Forwarding Wrapper in Root CLI Runner Script
Restored the root CLI runner script to only locate the package script in `Library/PackageCache/` or `Packages/` and forward arguments via `exec bash "$SCRIPT_PATH" "$@"`.
